packages system reference

hearth

The package manager. It builds from source, checks every download against a recorded checksum, and only allows dependencies on the approved list.

hearth -I <name>install

Builds a package from source. The dependency graph is checked first, and a cycle stops the run before anything is built.

If the package is not on the approved list, hearth refuses it.

rhea:rsh > hearth -I gcc
hearth: gcc is not on the approved list
hearth -Llist

Lists what is available. The repositories only carry software that already exists elsewhere on the internet, such as clang, LLVM, musl and the kernel. rhea's own tooling is not in them.

rhea:rsh > hearth -L
clang  llvm  musl  linux
install approvaloutput

Before anything is downloaded, hearth -I lists what it is about to install: each dependency and the package itself, with their versions and download sizes. Nothing starts until you answer.

[name] version [size]

rhea:rsh > hearth -I foo
[bar] v0.1.0 [5kb]
[foo] v1.2.3 [2mb]

want to approve the install [y/n]
install progressoutput

While hearth -I works, each package gets one line, and that line is updated in place as the package moves through its stages: downloading, then compiling, then installing. Only the current stage is shown at any time. The first part counts finished packages against the total. During compiling the counter shows files built out of files in total, and the other stages show a percentage.

[done/total]  name  version  [stage]  [progress]  [bar]

[0/1]  foo  v1.2.3   [compiling]    [20/282]  [██░░░░░░░░░░░░░░░░░░░░░░░░░]
hearth -S <name>search

Searches the available recipes. Each result is one line with the version, the app name and the repository it comes from.

[version] [appname] [repo]

rhea:rsh > hearth -S foo
v1.2.3  foo  main
hearth -Uupdate

Updates installed packages. rhea-linux is rolling, so this brings the system to the latest recipes. Outdated packages are rebuilt from source, with the same checks as an install and the same progress display.

rhea:rsh > hearth -U
[0/1]  foo  v1.2.4   [compiling]    [20/282]  [██░░░░░░░░░░░░░░░░░░░░░░░░░]
recipeformat

Every package has a recipe, a plain text file that tells hearth what to download and how to build it. This one is an example for llvm.

[name] = llvm
[version] = 23.1.3
[URL] = https://github.com/llvm/llvm-project/releases/download/llvmorg-23.1.3/llvm-project-23.1.3.src.tar.xz
[checksum] = sha256:...
[depends] = cmake ninja python

[build]
cmake -S llvm -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
ninja -C build

[install]
ninja -C build install

[name] and [version] identify the package. [URL] is where the source is downloaded from, and [checksum] is what hearth compares the download against before it uses it.

[depends] lists the packages that must be installed first. Hearth checks these for cycles before any build starts, and build tools such as cmake and ninja are listed here like any other dependency.

[build] and [install] are the commands hearth runs, one per line.

rsh

The shell, written for this system. These are the first commands it is planned to understand.

helpbuiltin

Shows the available commands.

rhea:rsh > help
help  rinfo  uname  ls  whoami  hearth  clear
uname -acoreutils

Prints the system name, host, kernel, architecture and libc.

rhea:rsh > uname -a
Linux rhea linux-lts x86_64 musl
ls [path]coreutils

Lists the contents of a directory.

rhea:rsh > ls /
bin  boot  dev  etc  home  proc  sys  tmp  usr  var
whoamicoreutils

Prints the current user name.

rhea:rsh > whoami
user
cat /etc/os-releasecoreutils

Shows the distribution identity. rhea-linux is rolling, so there is no fixed version number.

rhea:rsh > cat /etc/os-release
NAME="rhea-linux"
ID=rhea
VERSION_ID=rolling
clearbuiltin

Clears the screen.

ember

The init system. It is the first process the kernel starts, and it brings up everything else. A service is called a flame, and emberctl is the command-line tool for working with flames.

emberctl light <flame>start

Starts a flame.

emberctl snuff <flame>stop

Stops a flame.

emberctl stoke <flame>restart

Restarts a flame.

emberctl bank <flame>stop, keep ready

Stops a flame but keeps it ready to relight quickly.

emberctl peek <flame>status

Shows the status of a flame.

emberctl flameslist

Lists all flames that exist on the system.

emberctl douseshutdown

Shuts the machine down.

emberctl rekindlereboot

Reboots the machine.

emberctl -hhelp

Prints a short list of the commands.

rhea:rsh > emberctl -h
emberctl: control flames

  light <flame>    start a flame
  snuff <flame>    stop a flame
  stoke <flame>    restart a flame
  bank <flame>     stop, keep ready to relight
  peek <flame>     show a flame's status
  flames           list all flames
  douse            shut down
  rekindle         reboot

rinfo

System information next to the rhea logo, in the same spirit as fastfetch and neofetch, which rhea-linux does not use.

rinfotool

Prints the logo with the operating system, kernel, shell, libc, compiler and package count.

rhea:rsh > rinfo
user@rhea
---------
OS: rhea-linux x86_64
Kernel: linux-lts
Shell: rsh
Libc: musl
Compiler: clang
Packages: 0 (hearth)

errors

What rsh says when something is missing. Several tools from other systems are left out on purpose.

unknown commandrsh

Anything rsh does not know prints the name and says it was not found. This includes systemctl, sudo, fastfetch and neofetch.

rhea:rsh > systemctl
rsh: systemctl: not found
apt, pacman, dnf, ...rsh

Other package managers are not found, because rhea-linux has no binary packages.

rhea:rsh > apt
rsh: apt: not found. no binary packages.
